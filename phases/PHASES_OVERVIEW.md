# 分阶段开发总览

## P0 工程基础与契约

**目标：** 建立可测试、可替换、可追溯的工程骨架，冻结 Layout IR 1.1、作业状态机、Adapter 和模型网关契约。

**重要变更**：P0 新增四个前置控制任务（T0014-T0017），详见 `docs/23_MODEL_DEPLOYMENT_BASELINE_V1_1.md`。

**退出门槛：**
- 所有 JSON Schema 与样例验证通过
- CLI 可创建模拟作业并完成状态流转
- Mock 模型网关可被客户端调用
- 日志不包含正文
- 单元测试与 CI 基线通过
- 模型部署基线与文档对齐（T0014）
- 服务契约已冻结（T0015）
- 几何权威已验证或明确为待决策（T0016）
- 专项能力矩阵已完成（T0017）

任务数：17（原 13 + 新增 4）

## P1 纯电子 PDF MVP

**目标：** 在完全不依赖 OCR/VLM 的情况下，将正常电子 PDF 转换为基本可编辑 DOCX。

**退出门槛：**
- 黄金电子 PDF 文本和图片完整
- 正常原生文字 OCR 调用次数为 0
- DOCX 可打开
- 基本标题、段落、列表和图片顺序正确
- 无模型机时可运行

任务数：11

## P2 混合 PDF 与局部 OCR

**目标：** 完成页面/区域分流、Paddle 布局能力、局部 PP-OCRv6_medium、隐藏层去重和配图保留。

**退出门槛：**
- 混合 PDF 原生文字未被替换
- 局部扫描文字可编辑
- 普通配图整体保留
- 隐藏层无重复
- 所有区域有来源和路由记录

任务数：11

## P3 扫描 PDF 专项模型

**目标：** 完成纯扫描页面的文字、表格、公式和图片分区处理，以及安全降级。

**退出门槛：**
- 扫描正文可编辑
- 表格可重建或图片降级
- 公式可 OMML 或图片降级
- 图形区域不被误拆
- 专项模型失败不破坏作业

任务数：9

## P4 MonkeyOCRv2 与多模型融合

**目标：** 接入 MonkeyOCRv2 复杂版面主链路，加入 Ovis 内容复核和候选融合。

**退出门槛：**
- Monkey 经 8100 网关调用
- 坐标和标签归一化通过
- engine/system confidence 分离
- 复杂页阅读顺序改善
- Ovis 只按策略复核
- 影子评测报告完成

任务数：12

## P5 题目结构与高保真 DOCX

**目标：** 恢复题目层级、题图关系、表格/公式输出和稳定 Word 布局。

**退出门槛：**
- QuestionBlock 可用
- 题图自动/审校关系可用
- 右侧题图稳定
- 表格和公式按策略输出
- 长短题分页规则通过

任务数：15

## P6 QA 与人工审校

**目标：** 建立问题检测、回渲染、区域重识别、人工修正和审计闭环。

**退出门槛：**
- Issue 体系完整
- DOCX 完整性和回渲染可运行
- 审校修改有审计
- 区域可重识别
- 输出质量报告可下载

任务数：10

## P7 性能、安全、部署与发布

**目标：** 完成性能优化、模型机安全、打包、SBOM、运行手册和发布资格验证。

**退出门槛：**
- 性能基线达标
- 取消/恢复与清理通过
- 模型网关安全检查通过
- 模型/镜像版本固定
- SBOM/许可证完成
- 发布回归通过

任务数：12


## 阶段规则

- 不得在 P0 完成前实现业务流水线。
- P1 必须完全不依赖 GPU 模型机。
- P2/P3 先完成 Paddle 专项链路，再接 Monkey/Ovis。
- P4 的模型必须先影子运行，不直接替换基线。
- 每阶段退出必须生成验证报告和黄金集结果。
- 允许并行开发无依赖 Ticket，但不得跳过依赖和阶段门禁。
