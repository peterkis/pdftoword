# 00. 项目背景

## 1. 背景

用户需要将大量中文、英文及中英文混排 PDF 转换为 Word，主要文档包括：

- 纯电子制度、报告和标准；
- 数学、英语、化学试卷；
- 原生文字与配图、局部扫描片段并存的混合 PDF；
- 纯扫描或拍照 PDF；
- 表格、公式、几何图、实验装置图和化学结构图。

通用 PDF 转 Word 工具常见问题包括：

- 对电子 PDF 全文 OCR，平白引入错字；
- 只输出纯文本或 Markdown，丢失图文关系；
- 用大量绝对定位文本框模拟 PDF，Word 编辑后严重漂移；
- 把实验图或几何图中的标签拆成文字，破坏图形内部位置；
- 无法确定图片属于哪一道题；
- 公式、表格低置信度时仍强行生成错误的可编辑对象；
- 缺少识别来源、候选结果和人工审校机制。

## 2. 已确认的产品边界

目标不是 PDF 像素复刻，而是：

> 在不篡改内容的前提下，恢复主要文本、结构层级、阅读顺序和图文关系，输出稳定、可编辑、版式相似的流式 DOCX。

允许：

- Word 自然重分页；
- 局部布局发生合理重排；
- 复杂图文区域保留为图片；
- 低可信公式或表格降级为图片。

不要求：

- Word 与 PDF 页数一致；
- 逐行断行一致；
- 全页面绝对坐标一致；
- 所有复杂对象完全可编辑。

## 3. 运行环境

### 本地应用机

- 主要开发设备：Apple Silicon MacBook Pro，64GB 内存；
- 本地执行 PDF 原生解析、Layout IR、结构融合、DOCX 生成和审校；
- 桌面应用采用 Tauri 2 + React；
- Python Core 可独立作为 CLI 或本地服务运行。

### GPU 模型机

- Ubuntu 26 系统；
- NVIDIA RTX 5060 Ti 16GB；
- 负责 Paddle 专项模型、MonkeyOCRv2 和 OvisOCR2 推理；
- 统一模型网关端口 `8100`；
- 模型服务隔离，重模型受队列和显存策略控制。

## 4. 主要用户

- 需要本地处理敏感 PDF 的个人用户；
- 教师、试卷整理人员、科研和行政人员；
- 医院信息部门和知识库治理人员；
- 后续可作为知识库文档解析链路的 Word 重建输出端。

## 5. 成功标准

- 电子 PDF 不因 OCR 引入错误；
- 混合 PDF 只对必要区域识别；
- 题目和图片不发生错配；
- 扫描页能恢复主要可编辑内容；
- 表格、公式失败时可安全降级；
- 所有结果可追溯到页、区域、模型和原始资产；
- GPU 模型不可用时，纯电子 PDF 仍可转换。
